Qilin’s Infection Chain: Targeting 300+ EDR Drivers

A multi-stage Qilin infection chain uses a malicious msimg32.dll, in-memory execution and vulnerable drivers to disable security monitoring before ransomware deployment.

Qilin's EDR Killer

As endpoint detection and response tools become the standard for enterprise security, threat actors are continuously evolving their initial access phases to neutralize these defenses. The Qilin ransomware operation has recently been observed deploying a highly sophisticated infection chain. This campaign utilizes a customized EDR killer capable of disabling over 300 security drivers across various vendors. The attack architecture relies heavily on evasion, memory manipulation, and kernel-level exploitation to systematically dismantle security software before the final ransomware payload is delivered.

Initial Access and In-Memory Execution

The infection begins with a DLL sideloading technique. A legitimate executable, such as FoxitPDFReader.exe, is used to load a malicious version of msimg32.dll. To maintain the illusion of normal operation and avoid application crashes, the malicious DLL forwards standard API calls to the legitimate Windows library located in the System32 directory. The actual malicious payload triggers directly from the DllMain function. A multi-stage loader then decrypts and executes the core EDR killer component entirely in memory. This memory-only execution model ensures that the decrypted payload never touches the physical disk, severely limiting the artifacts available for traditional signature-based detection.

User-Mode Evasion and Syscall Bypassing

Before the malware attempts to interact with the kernel, the loader employs advanced user-mode evasion tactics to hide its activity from local sensors.

ETW Suppression: Event Tracing for Windows is suppressed at runtime. This deprives EDR solutions of the telemetry required for behavioral analysis. Halo's Gate Implementation (Syscall Bypassing): Security products typically place hooks inside ntdll.dll to monitor critical API calls. To bypass these, the malware utilizes a Halo's Gate technique. By scanning the ntdll.dll file forward and backward, it locates unhooked syscall stubs. It then repurposes these clean stubs to transition directly to the kernel, circumventing user-mode monitoring entirely.

Exception Handling Obfuscation: Control flow is obscured using Structured Exception Handling and Vectored Exception Handling mechanisms. The loader makes the .mrdata section of ntdll.dll writable and overwrites the exception dispatcher callback pointer, redirecting execution to its own custom routines. Anti-Analysis Checks: The malware actively monitors for hardware breakpoints on KiUserExceptionDispatcher. If a debugger is detected, the process is deliberately crashed to prevent security researchers from analyzing the execution flow.

Escalation via Vulnerable Drivers

To achieve the goal of terminating protected EDR processes, the malware must escalate its privileges to the kernel level. It accomplishes this by dropping two specific helper drivers onto the system.

rwdrv.sys (The Vulnerable Driver): This is a renamed version of ThrottleStop.sys, a legitimate driver signed by TechPowerUp LLC (commonly used in hardware monitoring tools like GPU-Z). Because it has a valid digital signature, it bypasses Windows Driver Signature Enforcement. However, this driver exposes highly privileged IOCTLs that allow arbitrary read/write access to physical memory. Qilin exploits this driver to directly manipulate kernel structures, executing a classic Bring Your Own Vulnerable Driver (BYOVD) attack. hlpdrv.sys: A dedicated driver used exclusively to terminate protected EDR processes via IOCTL code 0x2222008, bypassing standard Windows process protection mechanisms.

Neutralizing Kernel Monitoring Callbacks

Using the vulnerable driver's memory access, the malware targets over 300 EDR drivers by unregistering their critical monitoring callbacks, effectively blinding the security tools. To prevent system crashes (Blue Screen of Death) during this deep memory manipulation, it temporarily suspends Windows Code Integrity enforcement by overwriting the CiValidateImageHeader callback, restoring it afterward to hide its tracks.

Defense Implications

The Qilin campaign illustrates a strategic shift in ransomware deployment. Neutralizing the defense stack is treated as a primary operational objective rather than an afterthought. Protecting against these advanced evasion and vulnerable driver techniques requires environments to enforce strict driver blocklists, such as the Microsoft WDAC blocklist, alongside robust monitoring for anomalous DLL sideloading behaviors.
