HTB THREAT HUNTING GOOGLE CTF

OAuth Heist

A phishing-led cloud compromise unfolds across OAuth activity, stolen documents and database exfiltration.

By Mehmet Sacit Çınar · 1 November 2026

IN THIS WRITE-UP

Scenario Investigation Starting Point Question 1 Question 2 Question 3 Question 4 Question 5 Question 6 Incident Summary

Scenario

Welcome to the Cymbal Investments Security Operations Center. A high-priority threat bulletin from Google Threat Intelligence covering SHINYHUNTERS has landed in your Emerging Threats. Leveraging the full power of Google SecOps, from SIEM search and Curated Detections to Google Threat Intelligence (GTI) adversary reporting, your mission is to investigate the initial identity compromise and uncover the full scope of the incident.

Field Details
Platform HTB CTF - Operation Cymbal: Cold Room
Difficulty Easy
Category Threat Hunting
Environment Google SecOps
Reference Threat Actors Associated with the ShinyHunters Brand Expand Targeting of Cloud Applications for Extortion Operations.pdf
Author dmncdcco

Investigation Starting Point

The investigation began with the Google Threat Intelligence bulletin provided with the challenge, “Threat Actors Associated with the ShinyHunters Brand Expand Targeting of Cloud Applications for Extortion Operations.”

A search for SHINYHUNTERS in Emerging Threats returned several reports. The campaign “Threat Actor Targeting Multiple Cloud Platforms in ShinyHunters-Branded Data Theft Extortion Operations” was selected because its description aligned with the bulletin’s focus on credential harvesting, SSO account compromise, and data theft across cloud applications.

The campaign showed one matching IOC: 149.50.97.174. This IP address provided the starting point for the SIEM investigation.

Question 1

What is the phishing domain where employee credentials were submitted via an HTTP POST request? (expected format: domainname.com)

Reveal answer

Answer: sso-cymbal-portal.com

The IP address identified in the campaign’s IOC section was searched in SIEM Search:

Query / Log 
ip = "149.50.97.174"

The search returned two Zscaler HTTP events associated with elena.rostova.

The first recorded a GET request to the login page, followed by a POST request to the authentication endpoint. The POST event’s raw log contained:

Query / Log 
requestmethod=POST
url=https://sso-cymbal-portal.com/api/v1/auth/token
serverip=149.50.97.174
user=elena.rostova
status=200

The POST request identified sso-cymbal-portal.com as the phishing domain used to collect the employee’s credentials.

Question 2

To prevent the compromised employee from noticing the persistence mechanism, the adversary abused a newly authorized third-party OAuth application to permanently purge security notifications from the victim’s inbox. What is the exact subject line of the first permanently deleted email, which alerted on multi-factor authentication changes? (expected format: Hello! This is a fake email subject line)

Reveal answer

Answer: Okta: A new MFA factor was added

With elena.rostova identified in the phishing events, the investigation continued by searching for activity associated with her email address. The following prompt was entered into Generate Query:

Query / Log 
events related with elena.rostova@cymbal-investments.com

The generated query searched the user’s email address across user and email fields:

Query / Log 
principal.user.email_addresses = "elena.rostova@cymbal-investments.com"
OR target.user.email_addresses = "elena.rostova@cymbal-investments.com"
OR network.email.from = "elena.rostova@cymbal-investments.com"
OR network.email.to = "elena.rostova@cymbal-investments.com"

The results included two EMAIL_TRANSACTION events containing security notifications. The notification concerning an MFA change had the subject “Okta: A new MFA factor was added.”

Question 3

Continuing to monitor the compromised employee’s cloud activity from the attacker’s proxy infrastructure, what sensitive internal document did the adversary locate and download? (expected format: File_Name.extension)

Reveal answer

Answer: Cymbal_Q3_Database_Architecture_and_Service_Accounts.pdf

The same email-address query also returned a Google Drive item_download event. Its raw log showed that elena.rostova@cymbal-investments.com downloaded a PDF from 23.234.119.110, the attacker’s proxy IP.

The document name was recorded in the doc_title parameter. Relevant fields were:

Query / Log 
applicationName: drive
ipAddress: 23.234.119.110
name: item_download
doc_title: Cymbal_Q3_Database_Architecture_and_Service_Accounts.pdf
doc_type: pdf

Question 4

Armed with credentials discovered in the stolen document, what privileged service account did the attacker authenticate to from the compromised employee’s workstation to access the internal database server? (expected format: username)

Reveal answer

Answer: svc_dbadmin

The phishing event examined in Question 1 recorded the employee’s workstation IP as 10.240.12.65. To investigate subsequent authentication activity involving that workstation, the following query was run:

Query / Log 
ip = "10.240.12.65"

The results included a USER_LOGIN event at 2026-10-15T21:32:40, showing authentication under svc_dbadmin. This identified the privileged service account used in the next stage of the intrusion.

Question 5

Once authenticated to that internal server, what is the file name of the raw database dump exported by the attacker prior to compressing it into an archive? (expected format: file_name.extension)

Reveal answer

Answer: cymbal_cust_q3.bak

Activity associated with the service account was searched using:

Query / Log 
principal.user.userid = "svc_dbadmin" OR target.user.userid = "svc_dbadmin"

The results included a PROCESS_LAUNCH event for sqlcmd.exe, launched by wsmprovhost.exe. Its raw log contained the database backup command:

SQL 
BACKUP DATABASE [CymbalWealthMaster]
TO DISK='C:\ProgramData\MSSQL\Backup\cymbal_cust_q3.bak'
WITH FORMAT, COMPRESSION=OFF

The command exported CymbalWealthMaster to cymbal_cust_q3.bak, with backup compression disabled.

Question 6

What is the full exfiltration URL (including destination IP and port) used by the attacker to transfer the compressed archive? (expected format: http://8.8.8.8:0000/path/file_name.extensions)

Reveal answer

Answer: http://142.11.200.188:8888/upload/cymbal_q3_exfil.tar.zst

The same service-account search returned a NETWORK_HTTP event involving 142.11.200.188. Opening its raw log revealed a POST request containing the compressed archive’s destination URL:

Query / Log 
requestmethod=POST
url=http://142.11.200.188:8888/upload/cymbal_q3_exfil.tar.zst
user=svc_dbadmin
status=200

The request identified the destination IP, port 8888, upload path, and archive name cymbal_q3_exfil.tar.zst. The server returned HTTP 200.

Incident Summary

  1. Credential harvesting: Elena Rostova accessed sso-cymbal-portal.com from workstation IP 10.240.12.65. A GET request to the login page was followed by a POST to /api/v1/auth/token on 149.50.97.174.
  2. Identity persistence and notification removal: The attacker added an MFA factor to the compromised account. As described in the challenge, a newly authorized OAuth application was then abused to permanently delete security notifications, including “Okta: A new MFA factor was added.”
  3. Cloud document theft: Using the compromised employee’s cloud identity from proxy IP 23.234.119.110, the adversary downloaded Cymbal_Q3_Database_Architecture_and_Service_Accounts.pdf from Google Drive.
  4. Service-account access: Credentials obtained from the stolen document were used to authenticate as svc_dbadmin from the employee’s workstation and continue toward the internal database server.
  5. Database export: Under svc_dbadmin, wsmprovhost.exe launched sqlcmd.exe. The SQL command backed up CymbalWealthMaster to C:\ProgramData\MSSQL\Backup\cymbal_cust_q3.bak without SQL backup compression.
  6. Archive preparation: Subsequent service-account activity included execution of zstd.exe. The archive later observed in the outbound transfer was named cymbal_q3_exfil.tar.zst.
  7. Data exfiltration: The archive was transferred through an HTTP POST to http://142.11.200.188:8888/upload/cymbal_q3_exfil.tar.zst. The Zscaler record showed a 200 response.
