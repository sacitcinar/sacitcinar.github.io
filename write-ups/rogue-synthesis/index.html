HTB AI MISUSE GOOGLE CTF

Rogue Synthesis

A malicious VS Code extension leads to token theft and persistence in a CI/CD build pipeline.

By Mehmet Sacit Çınar · 1 November 2026

IN THIS WRITE-UP

Scenario Investigation Starting Point Investigation Question 1 Question 2 Question 3 Question 4 Question 5 Question 6 Incident Summary

Scenario

Cymbal Investments' Threat Hunting team has received an intelligence bulletin regarding AI threats. Armed with Google Threat Intelligence (GTI) reporting and Google SecOps SIEM, your mission is to hunt down the initial compromise and identify the adversary's ultimate target in our CI/CD pipeline.

Field Details
Platform HTB CTF - Operation Cymbal: Cold Room
Difficulty Medium
Category AI Misuse
Environment Google SecOps
Evidence Google Threat Intelligence bulletin, Zscaler HTTP logs, and Windows Sysmon events
Author dmncdcco

Investigation Starting Point

The investigation began with the intelligence bulletin supplied with the challenge, “GTIG AI Threat Tracker: Advances in Threat Actor Usage of AI Tools.”

On page 3, the PROMPTFLUX code example showed a function that queried the Gemini API. The code specified gemini-1.5-flash-latest as the model and generativelanguage.googleapis.com as the API host. This address provided the starting point for the SIEM investigation.

Investigation

Question 1

What developer username initiated a request to the model used by our AI threat? (expected format: user.name)

Reveal answer

Answer: alex.chen

The API host identified in the bulletin was searched in SIEM Search:

Query / Log 
target.url = /generativelanguage.googleapis.com/ nocase

The search returned one Zscaler NETWORK_HTTP event. Its raw log showed a POST request to the gemini-1.5-flash-latest model, associated with alex.chen and workstation IP 10.240.12.80. Relevant fields were:

Query / Log 
requestmethod=POST
url=https://generativelanguage.googleapis.com/v1beta/models/gemini-1.5-flash-latest:generateContent?key=[REDACTED]
clientIP=10.240.12.80
user=alex.chen
status=200

The request identified alex.chen as the developer username that initiated the API query.

Question 2

What package was downloaded immediately prior to the API query? (expected format: File_Name.extension)

Reveal answer

Answer: SyntaxOptimizer-2.1.4.vsix

With the username and workstation IP identified, related activity was searched using:

Query / Log 
principal.user.userid = "alex.chen" OR principal.ip = "10.240.12.80"

The search returned 27 events. Examining the activity before the API query revealed a GET request for a VS Code extension package. The raw log recorded:

Query / Log 
requestmethod=GET
url=https://marketplace.visualstudio.com.cdn-cache.net/extensions/DevTools/SyntaxOptimizer/2.1.4/SyntaxOptimizer-2.1.4.vsix
clientIP=10.240.12.80
user=alex.chen
status=200

The filename at the end of the URL identified the downloaded package as SyntaxOptimizer-2.1.4.vsix.

Question 3

Following the outbound API request, what compiled executable was dropped into the local directory used by the malware for staging? (expected format: file_name.extension)

Reveal answer

Answer: sys_worker.exe

The same user/IP search showed a cache_worker.c file creation event after the API request, followed by a PROCESS_LAUNCH event for gcc.exe, launched by node.exe.

Opening the GCC event's raw log revealed the compilation command:

Query / Log 
gcc.exe -O2 C:\Users\alex.chen\AppData\Local\Temp\cache_worker.c -o C:\Users\alex.chen\AppData\Local\Temp\sys_worker.exe

The -o argument specified sys_worker.exe as the output executable in the user's temporary directory.

The parent command line connected the compilation to the installed SyntaxOptimizer extension:

Query / Log 
node.exe "C:\Users\alex.chen\.vscode\extensions\devtools.syntaxoptimizer-2.1.4\out\optimizer-daemon.js"

The Sysmon event also identified the workstation as CYM-DEV-WS-019.cymbal.corp.

Question 4

After elevating privileges via process hollowing on the developer’s workstation, what existing file in the user’s local cloud SDK configuration directory was read by the injected process to harvest tokens? (expected format: file_name.extension)

Reveal answer

Answer: credentials.db

The workstation hostname obtained from the GCC event's Computer field was used to examine its local activity:

Query / Log 
principal.hostname = /CYM-DEV-WS-019/ nocase

The results included a PROCESS_LAUNCH event for cmd.exe, launched by svchost.exe. Its command line read a file from the user's local cloud SDK configuration directory:

Command Prompt 
cmd.exe /c "type C:\Users\alex.chen\.gcloud\credentials.db"

The type command identified credentials.db as the file read during token harvesting.

Question 5

Shortly after the local tokens were harvested on the workstation, the stolen data was exfiltrated via an outbound HTTP POST request to an external URI path masquerading as a telemetry endpoint. To what external domain was the data sent? (expected format: domain-name.com)

Reveal answer

Answer: dev-metrics-cdn.com

The investigation returned to the user/IP search from Question 2:

Query / Log 
principal.user.userid = "alex.chen" OR principal.ip = "10.240.12.80"

A subsequent Zscaler NETWORK_HTTP event showed a POST request to an external telemetry path. Its raw log contained:

Query / Log 
event_timestamp=2026-10-15 20:39:05
requestmethod=POST
url=https://dev-metrics-cdn.com/api/v2/telemetry
serverip=172.67.210.44
clientIP=10.240.12.80
user=alex.chen
status=200

The request identified dev-metrics-cdn.com as the destination domain. The /api/v2/telemetry path matched the telemetry endpoint described in the question, and the server returned HTTP 200.

Question 6

Using the harvested service account to pivot laterally from the developer’s workstation to a secondary server, what PowerShell script was overwritten by the attacker via PowerShell to establish persistence? (expected format: file_name.extension)

Reveal answer

Answer: build_production.ps1

The workstation search from Question 4 also returned a NETWORK_CONNECTION event involving svc_cicd_deploy and CYM-CI-RUNNER-01.cymbal.corp. This exposed the service account used to reach the CI server.

Activity associated with that account was then searched using:

Query / Log 
principal.user.userid = "svc_cicd_deploy"

The search returned three events: the connection to the CI server, a launch of wsmprovhost.exe, and a file event for build_production.ps1.

The file event's raw log was a Sysmon Event ID 11 on CYM-CI-RUNNER-01.cymbal.corp. Relevant fields were:

Query / Log 
UtcTime: 2026-10-15 21:48:25.000
Image: C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe
TargetFilename: C:\BuildRunner\scripts\build_production.ps1
User: CYMBAL\svc_cicd_deploy

The event linked PowerShell running under the service account to C:\BuildRunner\scripts\build_production.ps1, identifying the build script targeted for the persistence described in the challenge.

Incident Summary

  1. Extension download: Alex Chen's workstation downloaded SyntaxOptimizer-2.1.4.vsix through an HTTPS GET request. The extension later appeared in the parent command line associated with payload compilation.
  2. AI API interaction: A POST request associated with alex.chen queried gemini-1.5-flash-latest through the Gemini API. A local thinking_robot_log.txt file creation event followed the request.
  3. Payload compilation: The extension's optimizer-daemon.js ran through node.exe, which launched GCC to compile cache_worker.c into sys_worker.exe in the user's Temp directory.
  4. Token harvesting: Following the process-hollowing stage described in the challenge, svchost.exe launched cmd.exe to read C:\Users\alex.chen\.gcloud\credentials.db.
  5. Outbound transfer: The workstation sent an HTTPS POST to https://dev-metrics-cdn.com/api/v2/telemetry. The Zscaler log recorded a 200 response.
  6. Lateral movement: Workstation activity showed svc_cicd_deploy connecting to CYM-CI-RUNNER-01.cymbal.corp. Subsequent account activity included wsmprovhost.exe.
  7. CI/CD persistence: On the CI server, PowerShell running as CYMBAL\svc_cicd_deploy generated a file event for C:\BuildRunner\scripts\build_production.ps1, the script overwritten to establish persistence in the build pipeline.
