PCAP Behavior Core

An offline CLI tool that analyzes network behavior in PCAP files. Identifies scanning patterns, periodic connections and DNS activity, with supporting evidence in JSON and interactive HTML reports.

Network behavior, backed by packet evidence

PCAP Behavior Core examines captured network traffic and brings observable behavior into a single report. Analysis runs locally, and the generated HTML report can be explored without a server or internet connection.

From capture to findings

  1. Read the capture.

    Parse packets and organize network activity into flows.

  2. Examine the behavior.

    Evaluate TCP scanning patterns, connection timing, DNS activity and traffic characteristics.

  3. Present the evidence.

    Report endpoints, connection counts and time windows, with packet references that help trace each finding back to the capture.

What it includes

  • TCP scanning patterns across destination ports and IP addresses.
  • Periodic TCP connections and timing consistency.
  • Matched DNS queries and responses, including concentrated NXDOMAIN activity.
  • Long-duration TCP flows and outbound traffic volumes.
  • FTP control commands and server responses, with credentials and file paths excluded from the report.
  • Structured JSON output and a standalone interactive HTML report.
  • Python 3.10+ with no external runtime dependencies.

Run it locally

With Python 3.10+ and Git installed, clone the repository and install the tool:

›_ Installation
git clone https://github.com/sacitcinar/pcap-behavior-core.git
cd pcap-behavior-core
python -m pip install .

Analyze a capture:

›_ Analyze a PCAP
python -m pcapcore capture.pcap

Save the reports to a custom location:

›_ Custom output
python -m pcapcore capture.pcap -o results/analysis.json

The command produces both JSON and HTML output.

A look at the report

Reading the result

Findings describe observed behavior rather than confirmed attacks. Legitimate automated activity can produce similar patterns, while incomplete captures and encrypted traffic can limit visibility. Review each finding alongside its evidence and the wider investigation context.

Current Limitations

  1. Protocol coverage:

    HTTP request, TLS handshake and DNS-over-TCP analysis need to be added. Important context can currently be missed.

  2. Packet reassembly:

    General TCP stream and IP fragment reassembly are not available. These are needed to interpret content split across multiple packets correctly.

  3. PCAPNG support:

    PCAPNG input is currently explicitly rejected; users must convert the file.

  4. Large files:

    Although SQLite is used, all flows and DNS events are kept in memory. RAM usage and processing time should be measured on large captures, and this design should be improved.
